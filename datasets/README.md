# Датасеты

Приложение использует готовые наборы из `prepared/`: Восток (66 заявок), Юго-восток (83 заявки) и Югоцентр (56 заявок). Для запуска приложения пересобирать данные не требуется.

- `raw/` — исходные CSV и контрольные распределения.
- `prepared/*.json` — заявки, бригады, ограничения и матрицы переездов.
- `prepared/*.geometry.json` — геометрия маршрутов для карты.
- `samples/` — примеры CSV и JSON для импорта через интерфейс.

Координаты заданы в градусах, длительности и время переездов — в минутах, расстояния в матрицах — в метрах. Пользовательские окна времени задаются в формате `HH:MM`.

## Свои данные в интерфейсе

Примеры: `samples/orders.csv` (8 заявок, cp1251) и `samples/scenario.json`
(8 заявок, 3 бригады, UTF-8). Координаты относятся к Востоку. Импорт собирает
PreparedDataset v3 в памяти; исходные файлы и подготовленные наборы не меняются.
День, часовой пояс, модельная смена, допущения и матрицы берутся из выбранной территории.
События базового набора не переносятся. Новые точки добавляются только в `points`,
порядок и размеры матриц сохраняются. Переезды к ним — гаверсинус × коэффициент модели,
с явной отметкой приближения в плане; совпадающие координаты используют подготовленную точку.

### CSV

Разделитель `;`, кодировка cp1251 или UTF-8. Формат синтетического файла кейса:
`Заявка;Тип заявки BK;Тип заявки HD;Начало;Окончание;Район;Адрес;Подключение;Гигабитное подключение;Широта;Долгота`.
Даты `DD.MM.YYYY H:MM` должны соответствовать дню территории. Последняя служебная строка
`Адрес офиса` с адресом во второй ячейке и остальными пустыми ячейками обязательна по формату кейса;
старты и состав бригад берутся из выбранной территории, служебный адрес их не переопределяет.
`Гигабитное подключение` — `Да` / `Нет`, `Подключение` — `FTTB`, `FMC` или пусто.
Широта и долгота необязательны, но задаются вместе (десятичная точка или запятая).
Без них адрес сопоставляется по полной нормализованной форме (включая корпус и строение);
при нераспознанном формате — по строке без учёта регистра и крайних пробелов.
Совпадения только по улице недостаточно. Несопоставленная строка отклоняет весь файл.
Инженеры в CSV не задаются; используются все бригады территории.
Нормативы, приоритет, навык, транспорт и расход оборудования — общие таблицы dataset/prepare.

### JSON

Объект `{ "orders": [...], "engineers": [...] }`, оба массива непустые.
Индексы ошибок начинаются с 1. ID уникальны внутри каждого массива.

- Заявка: `id`, `lat`, `lon`, `window: {start, end}`. Укажите либо `bkType` и `hdType`
  из справочников кейса, либо все три поля `durationMin`, `skill`, `priority`.
  Явные значения этих трёх полей заменяют значения таблиц; авария всегда длится 100 минут.
  Необязательны `address`, `district`, `connection`, `gigabit`, `transport`, `equipment`.
  Без BK/HD подписи выводятся из приоритета и навыка, HD — «Информация».
- Инженер: `id`, `name`, `lat`, `lon`, `shift: {start, end}`, `skills` (1–3 навыка),
  `transport`; необязательны `address`, `equipment`.
- Навыки: `local`, `connection`, `emergency`; приоритеты: `normal`, `connection`, `emergency`;
  транспорт: `car`, `bicycle`, `foot`, `public`.
- `equipment`: объект с четырьмя неотрицательными целыми остатками/расходами:
  `emergency-kit`, `router`, `tv-box`, `cable-kit`. По умолчанию расход — по HD,
  утренний запас — по навыкам автомобильной бригады, для прочего транспорта нулевой.
- Время — `HH:MM`. Окно начала заявки пересекается с модельной сменой территории;
  отсутствие пересечения — ошибка. Индивидуальные смены инженеров должны лежать внутри
  модельной смены. Выполнимость заявки у конкретной бригады определяет планировщик.

Настройки территории описывают значения по умолчанию; явные поля JSON сохранены
в заявках/инженерах и доступны в экспорте результата. SHA-256 пользовательского файла
не вычисляется (`sources[].sha256` пуст); имя файла и номер записи сохраняются.
